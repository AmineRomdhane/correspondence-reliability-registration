# Correspondence Reliability Prediction for Point Cloud Registration

This repository contains a clean reproducible version of the code and experiment outputs for the study:

**Reliability Weight Prediction for Candidate Correspondences in 3D Point Cloud Registration**

## Context

Rigid point cloud registration is a key component in simultaneous localization and mapping (SLAM) and lifelong mapping. In practical CAD-to-scan and scan-to-scan situations, candidate correspondences can contain false matches caused by noise, partial overlap, different point densities, repeated structures, and scene changes.

This project studies whether a lightweight machine-learning model can predict reliability weights for candidate correspondences, and whether these weights improve one-shot rigid registration.

## Method Summary

The pipeline is:

1. Generate synthetic point-cloud pairs with controlled transformations, noise, partial overlap, and outliers.
2. Curate real CAD/scan registration cases used as pseudo-ground truth.
3. Extract candidate correspondences after an initial alignment.
4. Compute geometric and descriptor-based features.
5. Train a multilayer perceptron (MLP) to predict correspondence reliability.
6. Use predicted weights in a one-shot weighted Singular Value Decomposition (SVD)-based registration solver.
7. Compare against an unweighted one-shot SVD baseline.

## Reproducing the Synthetic Experiments

The synthetic experiments can be reproduced directly from this repository because the synthetic point-cloud pairs are generated by code. No external CAD or scan files are required.

### Step 1: Generate the synthetic point-cloud cases

Run:

    python3 src/create_multi_shape_synthetic_cases.py

This creates synthetic point-cloud pairs with controlled rigid transformations, noise, partial overlap, outliers, and scene changes.

### Step 2: Extract candidate correspondences and features

Run:

    python3 src/extract_correspondence_dataset.py

This step generates candidate correspondences after an initial alignment and computes the feature vector for each candidate correspondence.

The main generated dataset is saved under:

    results/learning_data/

### Step 3: Analyze the correspondence features

Run:

    python3 src/analyze_feature_correlations.py

This produces feature-correlation tables and figures used to study which features are most related to correspondence reliability.

### Step 4: Train baseline models

Run:

    python3 src/train_decision_tree.py
    python3 src/train_random_forest.py

These scripts train classical machine-learning baselines.

### Step 5: Train the MLP reliability model

Run:

    python3 src/train_mlp_pytorch.py

This trains the multilayer perceptron (MLP) that predicts the reliability weight of each candidate correspondence.

### Step 6: Run the unseen synthetic registration comparison

Run:

    python3 src/run_unseen_synthetic_registration_comparison.py \
      --seed 888 \
      --voxel-size 0.05 \
      --max-corr-distance 0.30 \
      --weight-threshold 0.0 \
      --init-rx-deg 3.0 \
      --init-ry-deg -2.0 \
      --init-rz-deg 12.0 \
      --init-tx 0.10 \
      --init-ty -0.07 \
      --init-tz 0.04

This compares:

- initial transform
- one-shot unweighted SVD
- MLP-weighted SVD
- ground truth

The output tables and figures are saved under:

    results/by_test/unseen_synthetic_registration_comparison/

## Expected Synthetic Result

For the unseen synthetic case with seed 888 and the perturbation shown above, the expected trend is:

- MLP-weighted SVD improves over the initial transform.
- MLP-weighted SVD improves over one-shot unweighted SVD.
- The result remains worse than the ground-truth transform.

In the reported experiment, the MLP-weighted SVD reduced the error compared with the one-shot unweighted SVD baseline:

- RMSE improvement: about 4.2%
- translation-error improvement: about 11.2%
- rotation-error improvement: about 5.6%

This validates that the learned correspondence weights can improve one-shot rigid registration on unseen synthetic cases.

## Reproducing the Real-Data Experiments

The real CAD/scan experiments require the original raw CAD and point-cloud files. These files are not stored directly in this Git repository because they are large.

The real-data configuration file is:

    configs/dataset_samples_synthetic_plus_real_curated_clean_v3.csv

To fully reproduce the real-data correspondence extraction, the required CAD and scan files must be placed at the paths specified in this configuration file.

Once the raw data is available, run:

    python3 src/extract_correspondence_dataset_synthetic_plus_real.py

Then run the leave-one-real-case-out registration comparison:

    python3 src/run_v3_leave_one_case_registration_comparison.py \
      --test-difficulty medium \
      --init-rx-deg 1.0 \
      --init-ry-deg -1.0 \
      --init-rz-deg 5.0 \
      --init-tx 0.03 \
      --init-ty -0.03 \
      --init-tz 0.02 \
      --save-case-figures

The generated outputs are saved under:

    results/by_test/v3_leave_one_case_registration_comparison/

## Main Real-Data Result

In the leave-one-real-case-out v3 experiment, the MLP-weighted SVD method achieved similar nearest-neighbor RMSE to the unweighted SVD baseline, but improved transform-related metrics in most held-out real cases.

The MLP-weighted method outperformed the unweighted one-shot SVD baseline in:

- 66.7% of cases for translation error
- 75.0% of cases for rotation error
- 75.0% of cases for point-action RMSE

This suggests that learned correspondence reliability weights can reduce transform drift, although one-shot weighted SVD is not sufficient for fully robust real-case registration.

## Data Availability

Large raw point clouds, CAD files, and ROS bags are not tracked directly in this repository. They should be stored separately or added through Git LFS or an external archive.

The synthetic experiments are fully reproducible from the code in this repository. The real-data experiments are reproducible only when the corresponding raw CAD and point-cloud files are available.
